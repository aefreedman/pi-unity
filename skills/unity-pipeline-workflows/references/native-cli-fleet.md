# Exact targeting and shared Unity Editors

1. Distinct project copies can proceed independently, subject to shared external resources. Prefer a verified canonical absolute project root over names, globs, or ambient settings. In Unity CLI 1.0.1 `status --project-path` can treat a nonexistent path as a substring filter; validate the directory and the returned identity. When several instances share a root, verify the role/instance and use an advertised instance selector as needed.
2. Send every child and resumed agent the exact absolute root, authorized work and designated Editor operator. Selection is not persisted by Pi and is not a permission grant.
3. One operator owns Editor-changing work in a shared copy until terminal status and current-run evidence are captured. Suitable reads by other agents are not guaranteed immediate, parallel or snapshot-consistent. Coordinate source edits too: they can trigger imports and domain reloads without a CLI command.
4. Native command serialization is not multi-command ownership. Pipeline shared test status may be replaced, and detached jobs need not survive domain reload. A missing job, child exit or cancelled wait does not show that Editor work stopped. Report the exact target, selection, evidence/paths and uncertainty before handing off. This is cooperative guidance, not a lock against native callers.

Global CLI help or `unity commands` is not the exact Editor's capability catalog. Use project-targeted discovery and per-command help. Bound lists and logs; review raw output before sharing. Cloud Build and Pipeline Automation are authenticated remote services, separate from the local Editor Pipeline. Verify the intended organization/project and paging before claiming complete inventory.
